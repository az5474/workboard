# 업무보드 (workboard)

여러 사업의 오늘 할 일을 한자리에서 보는 웹앱.
기존 Electron 데스크톱 앱(v2.9)을 **PC·노트북·모바일 어디서나** 쓸 수 있게 웹으로 옮기는 중이다.

```
데이터   Supabase (Postgres + Auth + RLS)
호스팅   GitHub Pages 예정 (아직 배포 안 함)
프론트   빌드 없는 정적 앱 (HTML + ES 모듈 + CDN)
디자인   DESIGN-meta.md (Meta 디자인 시스템) 기반 · 2026-08-23 고도화
```

---

## 실행

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "C:\Users\이광열\Desktop\CLAUDE CODE\apps\workboard\serve.ps1"
```

`http://localhost:5173` 이 열린다. Ctrl+C 로 종료.

- **`-ExecutionPolicy Bypass` 를 빼면 실행되지 않는다.** Windows 가 .ps1 을 막는다.
- 파일을 더블클릭(file://)해도 안 열린다. 브라우저가 ES 모듈을 http 로만 불러온다.
- **localhost 는 이 PC 에서만 열린다.** 폰에서 쓰려면 배포가 필요하다.

### 화면만 볼 때는 `preview.html`

`http://localhost:5173/preview.html` — **로그인도 서버도 없이** 열리는 정적 화면이다.
가짜 사업·업무가 박혀 있고 모든 부품(버튼·배지·칩·알림·시트·토스트)이 한 페이지에 있다.
오른쪽 위 아이콘으로 밝게/어둡게를 돌려볼 수 있다.

화면을 고칠 때는 여기서 먼저 본다. 실앱은 로그인해야 안이 보여서 확인이 느리다.
**다만 실앱 마크업이 바뀌면 여기도 같이 고쳐야 한다.** 자동으로 따라가지 않는다.
(아이콘 모음만은 `index.html` 것을 그대로 가져다 쓴다. 사본이 아니다.)

## Supabase

- URL / publishable key 는 `src/js/config.js` 에 있다. 공개돼도 되는 값이다(RLS 가 막는다).
- **secret key 는 절대 코드에 넣지 않는다.** RLS 를 무시하고 DB 전체가 열린다.
- 스키마: `db/01_schema.sql` (실행 완료). 테이블 `projects` · `tasks` · `trips`, 전부 RLS 적용.
- 로그인: 이메일 매직링크. 비밀번호 없음.

## 지금까지 된 것

**데이터 이관 완료** — 데스크톱 앱의 사업 5개 · 업무 52개가 Supabase 로 넘어갔다.

**보드 화면**
- 상단 요약(오늘 할 일 · 완료 · 지연 · 곧 마감) 한 줄
- 빠른 추가 (사업 · 제목 · 마감일)
- **핵심 3** — **사업마다 세 자리씩** 있다. `급한 순으로 채우기` 로 자동 선정
  - 전체 보기: `오늘의 핵심 3`. 고정된 것들 중 급한 순 3개를 보여주고,
    자리에 못 든 것은 아래에 `다른 사업의 핵심` 으로 사업별 개수를 적는다(눌러서 건너뛴다).
  - 사업 보기: `이 사업의 핵심 3`. 그 사업의 세 자리만 보인다.
- **빠른 추가** — 사업을 골라둔 상태로 들어가면 **그 사업이 자동으로 잡힌다.**
  사업을 골라놓고 다른 사업에 적어버리는 실수를 막는다.
- **사업별 오늘의 업무** — 사업 카드, 사업 색을 머리글에 옅게 사용
- **놓치고 있는 업무** — 오늘 목록에 없는데 마감 임박한 것 (`오늘로` 버튼)

**출장 달력** — 월 격자에 **기간을 막대 하나로 이어 그린다.**
하루씩 끊어 점으로 찍으면 사흘 출장인지 하루 출장인지 눈으로 셀 수가 없다.
주를 넘어가는 출장은 양 끝을 각지게 만들어 "아직 안 끝났다"를 표시한다.

- 막대 색은 **묶인 사업의 색**을 따른다. 사업을 안 고르면 회색이다.
- 사업 칩·사이드바로 걸러진다. 캠프 출장만 볼 수 있다.
- **빈 날짜를 누르면 그 날짜로 새 출장**이 열린다.
- 달력 아래에 그 달의 출장 목록이 있다. 기간·장소·사업과 `진행 중` · `3일 뒤` · `지남`.
- 좁은 화면에서는 막대에서 글자를 뺀다. 50px 칸에 글자를 우겨넣지 않고, 아래 목록에서 읽는다.
- **출장은 휴지통이 없다** (테이블에 `deleted_at` 이 없다). 지우면 토스트의 `되돌리기` 5초가 마지막 기회다.

**전체 목록 · 검색 · 휴지통 · 설정**

**업무 편집 시트** — 제목 · 사업 · 우선순위 · 상태 5종 · 마감일 · 메모 · 링크

**사업 관리** — 추가 · 이름 · 색상 · 보관 · **순서 변경**

순서는 `설정 > 사업 관리` 에서 손잡이를 끌어 바꾼다. 손잡이에 포커스를 두고
`↑` `↓` 로도 된다(마우스 없이, 폰에서도). 바꾼 순서는 **사이드바 · 사업 칩 ·
사업별 카드 · 빠른 추가의 사업 선택**까지 전부 따라간다.

**이월 자동화** — 앱을 열면 어제 못 끝낸 일이 오늘로 넘어온다.
`N회 이월` 은 **마감일이 없거나 이미 지난 업무에만** 오른다. 마감이 아직 남은 일은
오늘 목록으로 옮겨지기만 한다 — 다음 주 마감인 일이 매일 이월 배지를 다는 건
신호가 아니라 소음이다 (2026-08-24 수정. 그 전에는 무조건 +1 이었다).
5회 이상이면 `N회 밀림` (빨강) 으로 바뀐다. 계속 밀린다는 건 뭔가 막혔다는 신호다.

**밀린 업무 정리** (설정) — 지난 마감일 이동 · 이월 초기화 · 오늘로 끌어오기.
**자동으로 돌지 않는다.** 사용자가 필요할 때 직접 누른다.

**편의**
- 낙관적 업데이트 (화면 먼저 바꾸고 뒤에서 저장, 실패 시 되돌림)
- 완료 시 토스트에 `되돌리기` 5초 · **Ctrl+Z 로도 된다**
- 창 복귀 시 자동 재조회 (다른 기기 반영)
- 자정 넘김 감지 (1분 주기)
- 로딩 스켈레톤 · 오류 시 `다시 시도`
- 터치 타깃 44px (체크박스는 보이는 크기 22px)

**키보드** (입력창 밖에서)

| 키 | 하는 일 |
|---|---|
| `/` | 검색으로 |
| `N` | 새 업무 입력창으로 (모바일에서는 하단 가운데 ＋ 버튼) |
| `1` `2` `3` `4` `5` | 보드 · 전체 · 달력 · 휴지통 · 설정 |
| `←` `→` | 달력에서 지난 달 · 다음 달 |
| `Esc` | 시트 닫기 · 검색어 지우기 |
| `Ctrl+Z` | 방금 한 일 되돌리기 (토스트가 떠 있는 동안) |
| `Ctrl+Enter` | 업무 상세에서 저장 |

**시트** — Esc 로 닫히고, Tab 이 밖으로 새지 않고, 닫으면 원래 자리로 포커스가 돌아온다.
열려 있는 동안 뒷면은 스크롤되지 않는다.

**반응형**
| 화면 | 구성 |
|---|---|
| PC (1024↑) | 좌측 사업 사이드바 + 카드 2열 · 상단 알약 탭 4개 |
| 태블릿 | 사업 칩 가로 스크롤, 1열 |
| 모바일 | 하단 탭바 + 사업 칩, 본문 16px, 빠른 추가 2줄 |

**모바일 탭바는 다섯 자리뿐이다.** 보드 · 전체 · `＋` · 달력 · 설정.
휴지통은 어쩌다 한 번 열지만 달력은 일정을 확인하러 자주 연다.
그래서 **휴지통을 탭바에서 빼고 설정 맨 위 카드로 옮겼다.** PC 알약 탭에는 그대로 있다.

## 디자인 고도화 (2026-08-23 완료)

스킬 3종(`frontend-design` · `design-taste-frontend` · `emil-design-eng`)을 적용했다.
`design-taste-frontend` 는 스스로 "대시보드는 적용 범위 밖" 이라고 밝히므로,
거기서는 **AI 티 목록**과 **일관성 규칙(모양·색·테마)** 만 가져다 썼다.

바꾼 것:

- **아이콘** — `◐ ⚙ ＋ ✕ ◧ ☰ 🗑 ★☆` 이모지를 전부 걷어내고 `index.html` 의
  SVG 스프라이트(선 굵기 1.6 통일)로 교체했다. 이모지는 기기마다 다른 그림이 나온다.
- **글자 굵기** — 전부 700 이던 것을 400 / 500 / 600 / 700 네 단으로 나눴다.
  위계를 크기가 아니라 굵기로 만든다.
- **모서리** — 규칙 세 개로 통일 (아래 "설계상 지켜야 할 것" 참고).
- **누르는 느낌** — 모든 버튼·칩·체크에 `:active` 축소, hover 는 `(hover: hover)` 안에만,
  focus-visible 전역 규칙.
- **다크모드 실수정** — 하드코딩 색을 걷어내고 밝게/어둡게 **양쪽 전부 WCAG AA 통과**를
  브라우저에서 계산으로 확인했다. 토스트와 선택된 상태 버튼은 밝기를 따라 뒤집히면
  글자가 사라져서 자기 색을 따로 갖는다.
- **오늘의 핵심 3** — 세 칸 슬롯이 됐다. 빈 자리도 자리로 남고, 누르면 가장 급한 일이 앉는다.
  "자리가 세 개뿐" 이라는 사실이 화면에 보여야 무엇을 뺄지 생각하게 된다.
- **요약 줄** — 알약 상자를 벗고 가는 밑줄만 남겼다. 상자를 줄이면 업무가 앞으로 나온다.
- **사업 색 팔레트** — 같은 명도·채도 축에서 고른 10색으로 **선택지**를 바꿨다.
  **이미 저장된 사업 색은 건드리지 않았다.** 시트를 열면 현재 색이 첫 칸에 그대로 있다.
- **레이아웃** — 카드 2열을 1280px → 1160px 로 당기고, 한 줄 목록에 읽기 폭을 걸었다.
  1024~1279 구간에서 업무 한 줄이 화면 끝까지 늘어지던 것을 막는다.
- 죽은 코드 정리 — `js/board.js`, 안 쓰이던 `.list-group-head`.

### 3. Supabase 에 주소를 등록한다

로그인 메일의 링크가 돌아올 주소다. 등록하지 않으면 **로그인이 안 된다.**

```
Supabase → Authentication → URL Configuration
  Site URL       https://<계정>.github.io/<저장소>/
  Redirect URLs  https://<계정>.github.io/<저장소>/
```

`db.js` 는 `emailRedirectTo` 를 현재 주소로 잡으므로 코드는 고칠 게 없다.

### 4. 경로

모든 참조가 상대경로(`./`)라 `github.io/저장소/` 같은 **하위 경로에서 그대로 돈다.**
manifest 의 `start_url` · `scope` 도 `./` 다. 절대경로를 새로 넣지 않는다.

### 겪은 것

- `gh` 로그인 토큰은 **Windows 자격 증명 관리자**에 들어간다. 어떤 PowerShell 창에서는
  그게 안 읽혀 계속 "로그인하라"가 떴다. **`git push` 는 별개인 Git Credential Manager 를
  쓰므로 그쪽으로 우회했다.** `gh` 가 안 잡히면 `git` 으로 밀면 된다.

```
        ├── migrate.js      dashboard.json → DB 변환
        ├── ui.js           아이콘 · 토스트 · 업무행 · 편집 시트
        ├── sortable.js     끌어서 순서 바꾸기 (무엇을 옮기는지는 모른다)
        ├── views.js        화면 렌더
        └── main.js         진입점 · 로그인 · 뷰 전환 · 키보드 단축키
```

`sortable.js` 는 사업을 모른다. 줄(`.sortrow`)과 손잡이(`.grip`)만 알고,
끝나면 새 순서의 id 배열을 돌려준다. 다른 목록에 순서 바꾸기가 필요해지면
`enableSort(상자, { onReorder, onStep })` 로 그대로 쓴다.

## 설계상 지켜야 할 것

- **id 를 바꾸지 않는다.** 기존 `p3`, `task-1786518879031-4nslf` 를 그대로 쓴다. 업무-사업 연결이 유지되고 같은 파일을 여러 번 올려도 중복이 안 생긴다(upsert).
- **`carried_count` 와 `work_date` 는 핵심 자산이다.** "며칠째 밀렸는지", "오늘 할 일로 올린 날짜". 우선순위 판단의 근거다.
- **`status` 에 CHECK 제약을 걸지 않았다.** 나중에 상태를 늘릴 때 막히지 않게.
- **날짜는 `todayStr()` 로 만든다.** `toISOString()` 은 UTC 라 하루가 밀린다.
  문자열을 Date 로 되돌릴 때도 `parseDate()` 를 쓴다 (`new Date('2026-08-05')` 는 UTC 로 읽혀 하루가 밀린다).
- **출장은 언제나 `start_date ~ end_date` 를 함께 본다.** 시작일만 보면 기간이 사라진다.
  달력 막대·목록·정렬이 모두 이 규칙 위에 있다.
- **달력 칸 높이는 CSS 가 계산한다.** JS 는 그 주에 막대가 몇 층인지(`--lanes`)만 알려준다.
  픽셀을 JS 에서 계산하면 좁은 화면 값이 JS 안에 박혀버린다.
- **칩은 최대 3개.** 넷 이상 붙으면 제목이 안 읽힌다. 급한 신호부터 자리를 준다.
- **두 섹션에 같은 업무를 겹쳐 보이지 않는다.** "놓치고 있는 업무" 는 오늘 목록에 없는 것만.
- **핵심 3의 정원은 사업마다 따로 센다.** 사업을 여럿 굴리는 사람에게 "오늘 세 개" 는
  앱 전체가 아니라 사업 하나 안에서의 이야기다. 캠프의 세 개와 세미나의 세 개는 다른 목록이다.
  `togglePin()` 이 같은 사업 안의 고정 수만 세는 이유다.
- **보고 있는 사업을 바꿀 때는 `setProjectFilter()` 만 쓴다.** `state.projectFilter` 를
  직접 대입하면 `notify()` 가 돌지 않아, 빠른 추가처럼 "지금 보는 사업"을 따라가야 하는
  것들이 소식을 못 받는다.
- **사업 순서는 `projects.sort_order` 하나만 본다.** 화면마다 따로 정렬하지 않는다.
  `fetchProjects()` 가 정렬해서 가져오고, `state.projects` 배열 순서가 곧 화면 순서다.
  순서를 바꾸는 곳은 `reorderProjects()` 한 군데뿐이고, 저장에 실패하면 되돌린다.

### 바깥에서 온 값 (2026-08-23 점검에서 실제로 뚫려 있던 것들)

DB 와 가져오기 파일에서 온 값은 그대로 화면에 얹지 않는다. 셋 다 실제 구멍이었다.

- **글자는 `escapeHtml()`.** 특히 **가져오기 미리보기의 경고 문구** — 사업명·출장명이
  그 안에 섞여 나오는데 이스케이프가 없었다. 남이 준 `dashboard.json` 을 열어보는
  화면이라 여기가 가장 위험했다.
- **색은 `safeColor()`.** `style="background:${색}"` 로 들어가므로 따옴표가 섞이면
  속성을 빠져나간다. `#rrggbb` 와 `var(--토큰)` 만 통과시킨다.
  `loadAll()` 과 `migrate.js` 두 길목에서 거른다 — 화면 여덟 군데에서 각자 검사하면 언젠가 빠뜨린다.
- **링크는 `safeUrl()`.** `href` 에 아무 문자열이나 넣으면 `javascript:` 가
  이 페이지 권한으로 실행된다. `http(s)` 와 `mailto` 만 연다.
  (`example.com` 처럼 적은 건 `https://` 를 붙여 살린다.)

새 화면을 만들 때 이 셋을 안 거치면 같은 구멍이 다시 생긴다.

### 화면 규칙 (어기면 티가 난다)

- **모서리는 세 가지뿐이다.**
  누르는 것(버튼·칩·배지·탭)은 알약 `--r-control`,
  바깥 상자(카드·알림·빈 상태)는 `--r-card`,
  상자 안의 것(업무행·입력칸)은 `--r-row`.
  이 밖의 값을 쓰지 않는다. 반경이 섞이면 규칙 없이 만든 화면처럼 보인다.
- **이모지를 아이콘으로 쓰지 않는다.** `index.html` 스프라이트에 `<symbol>` 을 추가하고
  `icon('이름')` 으로 부른다. 선 굵기는 1.6 으로 맞춘다.
- **색은 반드시 토큰으로.** CSS 에 `#` 값을 직접 적으면 다크모드에서 그 자리만 안 바뀐다.
  이번에 고친 버그가 전부 이것이었다.
- **hover 는 `@media (hover: hover) and (pointer: fine)` 안에만 둔다.**
  터치에서는 탭이 hover 로 잡혀 눌렀다 뗀 자리에 색이 남는다.
- **누를 수 있는 것에는 `:active` 축소를 준다.** 화면이 손을 알아들었다는 신호다.
- **`outline: none` 을 쓸 거면 대신 보이는 표시를 반드시 만든다.** 없으면 키보드로 못 쓴다.
- **글자 굵기는 400/500/600/700 네 단.** 전부 700 이면 아무것도 강조되지 않는다.
- **자주 하는 동작일수록 짧게.** 체크는 120ms, 시트는 260ms.
  `ease-in` 은 쓰지 않는다 (시작이 늦어 굼떠 보인다).
- **숫자에는 `font-variant-numeric: tabular-nums`.** 없으면 갱신될 때마다 폭이 흔들린다.
- **대비는 밝게·어둡게 양쪽에서 본다.** `preview.html` 을 열고 개발자도구 콘솔에서 잰다.
  옅은 바탕 위 글자는 `--overdue-ink` 처럼 `-ink` 토큰을 쓴다 (원색은 대비가 모자란다).
